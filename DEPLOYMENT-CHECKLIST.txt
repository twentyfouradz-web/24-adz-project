24Adz.com — Clean Source Deployment Checklist

SOURCE STRUCTURE
[ ] Upload the ZIP contents to the connected GitHub repository root.
[ ] Confirm wrangler.toml, package.json, workers/, public/ and migrations/ are
    directly under the repository root.
[ ] Preserve public/index.html and public/admin.html.
[ ] Do not delete historical SQL migrations.

CLOUDFLARE
[ ] Worker name: 24adz-api.
[ ] Main entry: workers/index.js.
[ ] Deploy command: npx wrangler deploy.
[ ] D1 binding: DB -> existing hey-mr-database resource.
[ ] R2 binding: IMAGES -> existing hey-mr-images resource.
[ ] Do not create a duplicate manual ASSETS binding; wrangler.toml declares it.
[ ] Verify required Worker secrets: ADMIN_PASSWORD, ADMIN_SESSION_SECRET,
    SUPABASE_URL and SUPABASE_ANON_KEY. Never expose secret values.

DATABASE SAFETY
[ ] Run: npx wrangler d1 migrations list hey-mr-database --remote
[ ] Compare remote migration history before applying anything.
[ ] Apply only migrations not already recorded as applied.
[ ] Verify the production districts/areas schema before applying migrations
    0013 or 0014. Do not blindly replay the full migration history.

LIVE WEBSITE TESTS
[ ] Homepage loads on www.24adz.com and 24adz.com.
[ ] Register, email confirmation, login, logout and password reset work.
[ ] My Ads opens and displays the signed-in user's ads.
[ ] Post Ad opens, validates, uploads images and publishes successfully.
[ ] Published ads remain visible after refresh.
[ ] Edit and delete work for the correct owner.
[ ] Chat and My24adz open and work.
[ ] Category, subcategory, district and area navigation work.
[ ] SEO URLs resolve to the correct page.
