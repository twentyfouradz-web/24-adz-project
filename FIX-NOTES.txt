CATEGORY AND FORM FIXES IN THIS UPDATE
- Homepage main category directory explicitly displays all eight main categories.
- Category/subcategory search selection resolves a clicked subcategory to its
  parent main category, then filters using both values.
- Post Ad form has all eight main categories and category-specific form fields.
- Client-created ads now persist details_json, including the selected subcategory
  and category-specific values; client edits also update details_json.
- Admin-managed category hierarchy remains D1-driven. Worker validates the active
  main category and verifies that a selected active subcategory belongs to it.
- Future active main categories/subcategories added through the admin category
  manager are read from D1; Worker category validation does not use a fixed list.
- Free listing rule defaults to 3 ads per email account every 30 days. Admin
  settings can change the limit and period. Error/UI wording now says per email.
- Newest-first sorting uses timestamps, not numeric conversion of UUID ad IDs.

AUTHENTICATION AND EMAIL
- Homepage loads Supabase JavaScript v2 and uses Supabase Auth signUp,
  signInWithPassword, resetPasswordForEmail, updateUser and signOut.
- Supabase email confirmation is required; mobile OTP is not used.
- Worker exposes /api/public/auth-config and /api/client/sync, then validates
  Supabase bearer tokens for all client API operations and maps the Supabase user
  to the D1 client profile using supabase_uid.
- Legacy D1 password hashing, Resend verification-token delivery, and custom
  client register/login/verify/reset endpoints have been removed from active code.
- SUPABASE_SERVICE_ROLE_KEY is not needed by the current browser auth flow and
  must never be exposed in homepage HTML.
- Supabase sends confirmation and password recovery emails. Configure SMTP in
  Supabase Dashboard (for example, Resend SMTP) for reliable delivery.

DEPLOYMENT SAFETY
1. Upload/commit the complete ZIP contents to the connected GitHub repository,
   preserving the repository root structure (wrangler.toml, package.json,
   workers/, public/, migrations/).
2. Cloudflare Worker Build settings expected for this repository root:
   Build command: None; Deploy command: npx wrangler deploy; Root directory: .
3. Before any remote migration, inspect production history:
   npx wrangler d1 migrations list hey-mr-database --remote
4. Apply only pending migrations. Do not blindly replay the complete migration
   history against the reused production database.
5. Deploy Worker only after checking bindings and secrets. Do not change the
   existing DB or IMAGES resource selections.
6. After deployment, test /api/health, /api/public/categories,
   /api/public/ads, Supabase registration + confirmation + login, posting,
   editing, deletion, image upload, and category/search filters.

AUTH + CATEGORY FORM REPAIR — 11 November 2026
- Register no longer keeps a newly-created Supabase session. The page tells the
  user to open the confirmation email and then explicitly log in.

  the Homepage syncs the verified Supabase identity to D1, signs out that
  temporary confirmation session, pre-fills the same email in Login, and asks
  the user to log in manually.
- Login accepts either the registered email address or the registered
  10-digit mobile number. Mobile login is resolved inside the Worker and the
  email address is never returned to the browser. Login attempts are rate
